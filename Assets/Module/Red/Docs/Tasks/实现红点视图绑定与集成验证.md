## 接入契约

`RedNotify : MonoBehaviour` 提供 `void Bind(IRedSystem service)`、`void Bind(IRedSystem service, string path)`、`void Unbind()`；Inspector 默认路径字段为 `path`，另配置必需的子标记 `GameObject` 和可选 UGUI `Text`，不按名称查找。单参 Bind 使用默认路径；双参只覆盖运行时路径，启停沿用运行时绑定；Unbind 清理运行时服务、路径及 token，保留 Inspector 默认字段。组件不自行寻找服务或轮询计数。显示、幂等、启停与失败行为以需求为准。

`public static class RedViewBinder` 提供 `public static void Bind(Transform root, IRedSystem service)`、`public static void Unbind(Transform root)`；快照范围、顺序、预校验、失败及身份保护见[页面绑定规则](../需求.md#生命周期与-ui)，不新增公开验证或绑定身份接口。

静态区域接入示例（Prefab 拖入 `staticViewRoot` 并填好各自默认路径；空路径的动态模板和池容器不纳入该扫描域）：

```csharp
var red = new RedSystem();                    // 组合入口持有并注入
RedViewBinder.Bind(staticViewRoot, red);        // 静态区域一次绑定
red.SetCount("DailyBonus", 1);
red.SetCount("DailyBonus", 0);

// 已有列表 presenter 显示或复用条目，无需每个红点另写脚本
item.gameObject.SetActive(false);
itemBadge.Bind(red, $"Mail.{mailId}");
item.gameObject.SetActive(true);                // 首次显示就是本条目的最新值

RedViewBinder.Unbind(staticViewRoot);           // 关闭／换会话，先清理所有相关根
RedViewBinder.Unbind(dynamicViewRoot);          // 含本会话动态条目与池对象
red.Dispose();
```

Binder 包含 inactive 且每次使用 Inspector 默认路径，不能扫描空路径模板；再次批量 Bind 也会覆盖双参设置的运行时路径。默认路径完整的新子页面可对其根 Bind；动态业务条目使用上面的双参方式。同业务对象临时隐藏直接启停，换业务 ID 时先隐藏、改绑再显示；跨页面／会话归池先 Unbind，不新增筛选器、路径模板或管理组件。

## 实施与接线

原 RedNotify 的 `path` 配置与显隐／数字显示职责可复用，内部绑定逻辑允许重写；采用 UGUI Text、Unity API 和序列化子标记，按下述 Bind／OnEnable／OnDisable 管理生命周期，不依赖旧全局取服务方式、IRedNotify 或框架。新代码及资源的 `.meta` 按本工程维护。

1. Bind 先校验参数和子标记，再结束旧订阅并保存新目标；禁用时不调用服务，仅保存配置。OnEnable 有配置才订阅，未绑定时按需求处理合法子标记。
2. 每次订阅开始前记录本次绑定身份；禁用、解绑、销毁或切换使其失效。初次回调同步发生，此时 token 尚未返回；Subscribe 返回后再次核对身份及启用状态，失效则立即释放返回 token，不登记到当前绑定。
3. OnDisable 释放 token、隐藏标记并保留运行时配置；Unbind／OnDestroy 清除运行时配置。回调仅更新所属有效绑定，旧回调不能覆盖新显示。
4. 订阅异常先由核心撤销未返回的 token；组件仅在本次身份仍有效时清配置、释放已取得 token 并隐藏标记，不能清除后来建立的绑定。异常交调用入口报告，Unity 生命周期中的异常由 Unity 报告。OnEnable 重订失败采用同一收尾。
5. 测试消费者在主线程创建服务，向生产者和多个组件注入接口，用 `Shop`、`Shop.Gold` 等测试路径驱动自身值。结束时停止生产、解绑全部视图、销毁服务，`finally` 清理测试对象。换会话先结束旧实例再创建并绑定新实例；消费者以会话标识拒绝旧异步结果，不让其写入新服务。
6. 批量 Bind 先获取含 inactive 的有序组件快照并无副作用预校验，再逐项调用内部绑定路径。每项在开始订阅前记录本次操作身份，区分幂等未变与新建／替换；不能把 Subscribe 返回后回调已建立的新身份冒认为本次所有。订阅阶段失败按需求逐项清理并抛 `AggregateException`，包含原始及清理异常；Unbind 的快照同时记录当时身份，清理一个成员引发的其他重绑不得被旧快照清除，收尾错误统一以 `AggregateException` 汇总。
7. 两个 Prefab 使用同一 RedNotify，子标记默认隐藏、组件引用预接；圆点无 Text，数字 Text 预接，所有装饰 Graphic 关闭 raycastTarget。可复用参考资源层级，但需重接本工程脚本／资源引用，不残留旧工程专属 GUID、UIText 或 XAsset 依赖；字体、sprite 等来自工程内或可用 Unity 内置资源。此处只做既定 Prefab 适配，不全量搬运资产；具体美术可选，但必须导入无丢失引用并实际显示。

## 必要验证

正常功能、Prefab 及生命周期集成使用真实 RedSystem；清理异常分支单独使用最小 IRedSystem／token 受控故障夹具验证，不代替真实集成，不增加生产公开接口。

- 设计审查：公共行为、Prefab 与页面接入体验符合文档，显示和订阅生命周期职责清楚，无旧框架耦合；必要取舍直接记在本任务，不按源码相似度验收。
- 未绑定 OnEnable：不订阅、不报绑定错误；仅隐藏合法子标记，空字段及宿主／祖先配置不被误操作。首次零值绑定后宿主仍启用，写正值直接显示；父子视图合计同步，多视图分别解绑。
- 显示与参数：无 Text 圆点显隐，有 Text 展示完整合计。字段缺失、非法子标记、非法路径、null 服务符合规定异常且原绑定不变；禁用 Bind 不调用服务探测。
- Prefab 与便利性：导入两个真实 Prefab，引用无丢失，默认子标记隐藏且装饰不挡点击；拖入静态区域只填 `DailyBonus` 等路径，一次 Bind 即驱动多个路径及同路径多个视图。验证 1／0 显隐和数字合计、默认路径完整的新子页面一次 Bind、池复用无重复监听；单参取默认路径、双参覆盖后启停保持覆盖，Unbind 后默认路径仍可再次使用。
- 批量绑定：含 root 自身、inactive、兄弟与嵌套组件，验证前序／sibling 顺序；无组件、null 参数、重复整页 Bind。末项路径或标记非法时全部原绑定不变；预校验后通过初刷销毁共享服务，制造后续订阅失败，确认只清理本次新建／替换且身份仍匹配者，旧已替换绑定不恢复，幂等及未处理者的运行时配置／身份不被 Binder 清除，且保留原错误；不要求继续收到已销毁服务通知，清理错误汇总由单独故障夹具验证。
- 批量身份保护：初刷回调将成员重绑到另一真实服务，后续项失败时保留该新绑定；确认操作身份在初刷前记录。Unbind 快照清理期间重绑后续成员，旧快照不得解绑新身份；单项清理失败仍继续其他成员，最终汇总。新出现组件不追加入当轮，已销毁成员跳过。
- 池复用：启用→禁用→业务修改→启用，立即显示最新值，无重复监听；销毁启用／禁用对象、重复 Unbind 都清理正确。反复 Bind 同实例同路径仍只接收一次；切换路径／服务、禁用时改配置均只保留最新绑定。
- 动态条目 A→B：真实池对象先隐藏，双参改绑到 B，再显示；首次显示即 B 最新值，A 后续更新无影响。重复身份切换不增长监听，清零并解绑后动态路径可回收。
- 初次回调窗口：给子标记添加一次性触发的测试组件，其 OnEnable 分别禁用宿主或调用 Unbind；设置正数后首次 Bind 激活子标记，Subscribe 返回时不得残留监听，之后重绑可恢复。静态检查异常分支也只清理本次身份，不清除后来建立的绑定。
- 订阅失败：用已销毁的真实服务分别触发启用时 Bind 失败、禁用 Bind 后 OnEnable 失败，均清配置／订阅、隐藏且异常可见；新服务可恢复。初次通知失败与上一项共同覆盖未返回 token 的清理。
- 清除：真实 ClearSubtree 使父子标记归零，订阅保留，重设恢复；再禁用／销毁视图可裁剪动态路径。
- 会话：推荐结束顺序无残留；旧 token 延迟释放、旧回调收尾和旧会话迟到结果不影响新服务。验证连续 Play；项目关闭 Domain Reload 时，再做该设置下的重复 Play，不为测试更改设置。

Unity 验证入口为导入、编译、`Module.Red.EditModeTests` 回归、`Module.Red.PlayModeTests` 及连续 Play。真实业务数据源、路径与组合入口的后续接线缺口记在下方执行记录与结果，模块测试只证明本次消费者闭环。

# Red 红点系统需求与实施

## 目标与范围

目标：以 TileScape 的实际功能与使用体验为基线，在用户指定的 `Assets/Module/Red/` 提供红点计数、父级汇总、变化订阅及 UGUI 显示。优先复用适用代码，允许为明确收益重构或重新实现内部逻辑；以功能与便捷性达标、错误收尾可靠、减少重复计算和无关结构衡量质量，不以代码相似度或是否重写判断。

- 业务方拥有路径命名、数据源与计算规则，写入某路径的自身值。红点核心只维护计数、树结构和订阅；父节点可以同时有自身值和子节点。
- 组合入口创建服务，将本地接口注入业务与视图，并负责结束该实例。独立服务之间状态隔离，不建立全局单例或服务定位器。
- 首版不包含持久化、服务端同步、业务计算回调、图结构多父节点、规则编辑器、优先级红点类型、帧末批处理或自动轮询。布尔显示由合计值是否大于零决定。
- 核心不依赖 Unity 对象；UGUI 适配负责对象生命周期。三包目前未提供红点、UI 或注册器 API，本模块不预造包级接线，也不迁移参考项目的依赖。

模块归属见[项目架构](../../../../Docs/Project/02_架构与模块.md)，执行与文档维护遵循[协作协议](../../../../Docs/Project/04_Agent协作协议.md)、[文档组织规范](../../../../Docs/Project/06_文档组织规范.md)及[工程标准](../../../../Docs/Project/05_工程实施与验收标准.md)。核心与视图共用本文规范，按能力组织行为、必要设计和验证；对应两个工作项分别交付，由视图工作项承担最终集成。

本文及显式规范依赖足以独立实现；TileScape 源码及公开资料用于对照，不是实施前置，内部复用或改写不改变公共契约与行为。多套实现采用共同验收并隔离工作区，避免同名类和程序集冲突。前置条件同时违规时允许报告任一匹配的错误，单一违规必须符合对应异常类型。

Unity 导入、编译和测试默认由用户执行；性能记录可复现耗时与分配，不预设零 GC。正式业务接线需单独验收，模块测试不能代替。

## 核心计数与通知

### 路径与计数

| 情境 | 要求与可判定结果 |
|---|---|
| 路径 | 以 `.` 分段，按 `StringComparer.Ordinal` 区分大小写；拒绝 null、空串、空段及任何空白字符，不自动修剪、改大小写或接受转义。`Shop`、`Shop.Gold` 是不同节点，`Shopper` 不属于 `Shop`。隐藏根只作容器，不对外寻址或累计计数。 |
| 自身值与合计 | 每个可寻址节点的合计 = 自身值 + 直接子节点合计；自身值为非负 `int`。设置 `Shop=2`、`Shop.Gold=3`、`Shop.Diamond.A=4` 后，查询 `Shop` 得 9，`Shop.Diamond` 得 4；隐式父节点可查询、写入和订阅。 |
| 修改完成 | 设置是覆盖自身值；先完整提交目标及全部祖先的合计，再开始同步通知。操作返回时整条链一致，不依赖 Update；回调查询任一相关节点也得到已提交值。重复设置同一自身值不通知。 |
| 未知路径 | 查询返回 0，且不创建节点；设置按需创建路径。有效路径的零值订阅允许先于业务数据存在。 |
| 清除子树 | `ClearSubtree` 将目标及后代的自身值归零，更新祖先，保留现有订阅。清除未知路径或再次清除均无通知；后续重新写值仍能驱动原视图。清除不影响兄弟分支。 |
| 边界与溢出 | 负值抛 `ArgumentOutOfRangeException`；任何可寻址节点合计超过 `int.MaxValue` 时整次设置抛 `OverflowException`，数值、树结构和通知均不改变。不同顶层独立累计，不因隐藏根求和溢出。null 路径抛 `ArgumentNullException`，空字符串及其他非法路径抛 `ArgumentException`。 |
| 节点回收 | 清零或最后一个订阅释放后，递归裁剪自身值为零、无订阅且无后代的节点；有订阅的零值路径保留。动态路径反复创建、清除、退订后不持续积累无用节点。 |

### 通知与失败

| 情境 | 要求与可判定结果 |
|---|---|
| 订阅 | 每次订阅返回独立 `IDisposable` token，并同步向新监听发送一次当前合计；同一委托订阅两次即有两份独立监听，释放一份不影响另一份。null 回调抛 `ArgumentNullException`。传入委托作为一次订阅调用；组合委托内部遵循 C# 调用语义，模块不拆分，异常隔离以订阅为单位。 |
| 变化派发 | 仅在合计变化时通知；受影响节点按绝对深度降序，同深度按完整路径 Ordinal 升序，同节点按注册顺序，每节点本轮最多一次。订阅本身不通知已有监听。 |
| 退订 | token 释放立即生效，重复释放安全；回调内可退订自身或其他监听，尚未开始的已退订监听不再调用。当前已进入的回调自然结束。 |
| 回调重入 | 通知期间允许查询、token 释放及所有者销毁服务；拒绝设置、清除和新订阅，抛 `InvalidOperationException`，包括同值写入与未知路径清除。首版不引入重入命令队列或递归通知。 |
| 变化回调失败 | 单个回调抛错后继续其余有效监听，整轮结束以 `AggregateException` 汇总原异常。数值已经提交，不回滚；调用方不可把通知异常当作写入未发生而盲目重试。 |
| 初次通知失败 | 初次回调抛错时，只撤销本次订阅并回收空节点，再抛 `AggregateException`，不留下未返回 token 的监听。不回滚回调已合法完成的其他退订或服务销毁；先退订／销毁再抛错仍汇总错误。 |

### 核心生命周期

| 情境 | 要求与可判定结果 |
|---|---|
| 线程 | 核心限定构建线程调用，跨线程操作抛 `InvalidOperationException` 且不改状态。Unity 宿主在主线程创建、绑定、写入与释放；构建线程亲和性不等于核心能识别 Unity 主线程。后台结果须由业务切回主线程并确认会话有效。 |
| 服务结束 | 所有者先停止数据生产、解绑视图，再销毁服务。销毁立即使实例失效并清除数值、监听与树；重复销毁安全，旧 token 可继续幂等释放。其他旧实例操作抛 `ObjectDisposedException`，不重建服务。 |
| 回调内销毁 | 即时失效，跳过尚未开始的监听，当前回调自然返回；有已捕获异常仍在外层收尾时汇总。初次订阅回调主动销毁服务且未抛错时，可返回已失效 token。旧回调收尾不得清理或改写新实例。 |

### 公开契约

```csharp
namespace Module.Red
{
    public interface IRedSystem
    {
        int GetCount(string path);
        void SetCount(string path, int ownCount);
        void ClearSubtree(string path);
        System.IDisposable Subscribe(string path, System.Action<int> callback);
    }
}
```

实现类为 `public sealed class RedSystem : IRedSystem, System.IDisposable`，提供公开无参构造 `RedSystem()` 和 `void Dispose()`。消费者持有接口，创建实例的组合所有者负责释放。路径、异常与生命周期语义见本章前述规则。

### 核心必要设计

1. **结构与所有权**：RedSystem 持有分段前缀树，管理订阅及派发生命周期；内部 RedNode 保存父节点、子节点、自身值、缓存合计及本节点订阅。隐藏根只作容器，隐式父节点可寻址；查询直接读取缓存，不扫描子树。不引入旧 IApplicationModule／IImplementManager、BettaSDK／Module.Basic、空 Update 或遥测等耦合。
2. **设置与清除**：SetCount 先校验路径、值及全部祖先候选合计，用较宽整数预计算差量，通过后才创建缺失节点、提交自身值和全部祖先增量，再通知。ClearSubtree 遍历目标子树归零，更正祖先合计、保留订阅再通知。清除与退订后裁剪无值、无订阅、无后代节点，并移除可选路径缓存项。
3. **通知与失败**：每次订阅持有独立 token，使用通知快照和异常隔离。初次回调也受派发保护；失败只撤销本次注册及空节点，保留合法退订／销毁结果。全部数据提交后，按[通知与失败](#通知与失败)的顺序逐项复查服务和 token 有效性、捕获异常，收尾后汇总；派发保护在 `finally` 恢复。
4. **生命周期**：Dispose 先失效再清理，旧派发只收尾旧实例，不影响新实例。线程、实例、重入及输入约束按本章落实，不自行切线程，多条件违规不规定检查优先级。
5. **测量后优化**：完整路径缓存、Split 或范围扫描依据测量选择；不改变公开行为，不引入全局缓存或未经需求支持的重入队列。

### 核心验证

- 设计审查：公共行为符合文档，计数与订阅职责清楚，无重复结构、无用继承或旧框架耦合；必要的复用／改写取舍简记对应工作项结果，不新增报告、来源副本或哈希材料。
- 计数：[路径与计数](#路径与计数)的 `Shop` 示例、隐式父节点、大小写／兄弟前缀隔离；回调查询全链已提交。未知查询不建树，同值不回调。
- 输入与原子性：null／空路径／空段／空白、负值、父级溢出均符合约定异常且不改状态；两个顶层分别达到 `int.MaxValue` 仍合法。
- 清除与回收：清除父、叶、未知路径及重复清除；原订阅保留并能恢复通知。动态路径创建、清零、退订循环后节点和可选缓存回到原规模，不新增公开测试 API。
- 订阅：初次仅刷新新监听，同委托多 token 独立、null 拒绝、组合委托按单次订阅调用、重复释放、回调内退订自身／后续监听。清除同时含 `A.X` 与 `A.B.Y` 的子树，验证绝对深度降序、同深度完整路径 Ordinal 升序和同节点注册顺序，每节点最多一次。
- 失败与重入：多监听抛错仍完成其余有效监听，汇总原异常且数据已提交；初次通知失败不留本次监听。初次回调分别“释放已有 token 后抛错”“销毁服务后抛错”，合法收尾保留且仍报告错误。通知内写值、清树、订阅拒绝，外层保护恢复。
- 生命周期：重复销毁、旧实例操作拒绝、旧 token 释放安全、跨线程失败；回调销毁跳过后续监听，初次销毁可返回失效 token，销毁与抛错组合仍收尾；旧实例不影响新实例。
- 性能：深度为 5、叶子数分别为 100 和 10,000 的两组树，固定路径深度与监听数量，在计时外建树和预热；交替写两个不同值，再查询可寻址祖先合计，避免只测同值无操作或叶子读取。另测动态创建／清除／退订、初次刷新与多监听，记录环境、迭代次数、耗时与分配。判据是稳定更新仅处理目标祖先及受影响监听、查询不扫描子树、动态节点可回收；不承诺固定毫秒或零 GC。声称比参考更快须同环境、同负载比较，不混用不同后端结论，也不为比较强制引入旧工程依赖或新框架。

Unity 验证入口为导入、编译及 Test Runner 的 `Module.Red.EditModeTests`；联合验证由[视图工作项](#实现红点视图绑定与集成验证)承接。

## 视图绑定与生命周期

### 视图行为与验收

| 情境 | 要求与可判定结果 |
|---|---|
| 显示 | 合计为 0 时隐藏标记，大于 0 时显示；可选 UGUI `Text` 显示实际合计，首版不做 `99+`、缩写或类型优先级。被切换显隐的对象必须是绑定组件宿主的子物体，不能是宿主自身或祖先，避免隐藏红点导致自动退订。 |
| 首次绑定与池复用 | Inspector 配置默认路径 `path`；`Bind(service)` 使用它，`Bind(service, path)` 仅覆盖本次运行时路径，不修改 Inspector 默认值。有运行时绑定配置时启用即订阅刷新，禁用时释放 token、隐藏标记并保留该配置；再次启用取得最新值。未绑定的 OnEnable 不订阅，仅隐藏已配置的合法子标记，无配置不算错误；未配置或非法标记在 Bind 时校验，不误操作宿主或祖先。销毁时解绑并释放引用。禁用 Bind 只保存配置，不调用服务探测是否已释放。 |
| 重复绑定与切换 | 同实例同路径重复绑定幂等。更换路径或会话实例时先结束旧订阅，再建立新订阅，不显示旧计数；旧 token 只关联旧实例。显式解绑清空运行时服务、路径及 token 并隐藏标记，保留 Inspector 默认配置。 |
| 绑定失败 | null service 抛 `ArgumentNullException`，路径沿用核心规则，标记缺失或不是合法子物体抛 `ArgumentException`；校验失败保留原绑定。有效非 null 服务是否已释放由实际 Subscribe 判断。首次或 OnEnable 订阅失败，若本次绑定仍有效，清配置、释放订阅、隐藏标记并报告异常；不清除后来建立的绑定，可显式重绑恢复。 |
| 页面绑定 | `RedViewBinder.Bind(root, service)` 快照 root 自身及后代（含 inactive）的 RedNotify，按 Transform 前序、同级 sibling 顺序使用各默认路径绑定。无组件无操作；null root／service 抛 `ArgumentNullException`。默认路径已配置的静态区域创建后调用一次，新子页面同理；动态业务路径由条目 presenter 在显示前双参 Bind，已绑定池对象启停自动恢复。扫描域与池复用示例见[接入契约](#接入契约)。辅助入口不常驻持有服务或 UI，不轮询层级，单组件绑定仍可用。 |
| 批量失败与解绑 | 批量 Bind 先无副作用校验全部快照成员路径和标记，失败保留原绑定；通过后逐个绑定，跳过已销毁对象，新组件留给下次调用。订阅阶段失败停止继续绑定，只清理本次新建／替换且身份仍匹配的绑定，不清理未处理者、原本相同的幂等绑定或回调中新建的绑定；已替换的旧绑定不恢复。逐项清理后以 `AggregateException` 汇总原始与清理异常。`Unbind(root)` 同样快照组件及当时绑定身份，仅清理仍匹配者，逐项继续并最终以 `AggregateException` 汇总错误；null root 抛 `ArgumentNullException`，无组件无操作。 |
| 可拖入视图 | 提供预接线的圆点 `Res/Red.prefab` 与数字 `Res/RedCount.prefab`，共用 RedNotify，合法子标记默认隐藏；数字 Text 已接好，圆点不配 Text，装饰 Graphic 不拦截射线。拖入后只填写路径，不需逐项连字段或写订阅脚本；资源来自工程内或可用 Unity 内置资源，不要求复刻参考美术或动画。 |

### 接入契约

`RedNotify : MonoBehaviour` 提供 `void Bind(IRedSystem service)`、`void Bind(IRedSystem service, string path)`、`void Unbind()`；Inspector 默认路径字段为 `path`，另配置必需的子标记 `GameObject` 和可选 UGUI `Text`，不按名称查找。组件不自行寻找服务或轮询计数。默认与运行时配置、显示、幂等、启停、解绑及失败行为见本章[视图行为与验收](#视图行为与验收)。

`public static class RedViewBinder` 提供 `public static void Bind(Transform root, IRedSystem service)`、`public static void Unbind(Transform root)`；快照范围、顺序、预校验、失败及身份保护见[视图行为与验收](#视图行为与验收)，不新增公开验证或绑定身份接口。

静态区域接入示例（Prefab 拖入 `staticViewRoot` 并填好各自默认路径；空路径的动态模板和池容器不纳入该扫描域）：

```csharp
var red = new RedSystem();                    // 组合入口持有并注入
RedViewBinder.Bind(staticViewRoot, red);        // 静态区域一次绑定
red.SetCount("DailyBonus", 1);
red.SetCount("DailyBonus", 0);

// 已有列表 presenter 显示或复用条目，无需每个红点另写脚本
item.gameObject.SetActive(false);
itemBadge.Bind(red, $"Mail.{mailId}");
item.gameObject.SetActive(true);                // 首次显示就是本条目的最新值

RedViewBinder.Unbind(staticViewRoot);           // 关闭／换会话，先清理所有相关根
RedViewBinder.Unbind(dynamicViewRoot);          // 含本会话动态条目与池对象
red.Dispose();
```

Binder 包含 inactive 且每次使用 Inspector 默认路径，不能扫描空路径模板；再次批量 Bind 也会覆盖双参设置的运行时路径。默认路径完整的新子页面可对其根 Bind；动态业务条目使用上面的双参方式。同业务对象临时隐藏直接启停，换业务 ID 时先隐藏、改绑再显示；跨页面／会话归池先 Unbind，不新增筛选器、路径模板或管理组件。

### 实施与接线

原 RedNotify 的 `path` 配置与显隐／数字显示职责可复用，内部绑定逻辑允许重写；采用 UGUI Text、Unity API 和序列化子标记，按下述 Bind／OnEnable／OnDisable 管理生命周期，不依赖旧全局取服务方式、IRedNotify 或框架。新代码及资源的 `.meta` 按本工程维护。

1. Bind 先校验参数和子标记，再结束旧订阅并保存新目标；禁用时不调用服务，仅保存配置。OnEnable 有配置才订阅，未绑定时按本章行为规则处理合法子标记。
2. 每次订阅开始前记录本次绑定身份；禁用、解绑、销毁或切换使其失效。初次回调同步发生，此时 token 尚未返回；Subscribe 返回后再次核对身份及启用状态，失效则立即释放返回 token，不登记到当前绑定。
3. OnDisable 释放 token、隐藏标记并保留运行时配置；Unbind／OnDestroy 清除运行时配置。回调仅更新所属有效绑定，旧回调不能覆盖新显示。
4. 订阅异常先由核心撤销未返回的 token；组件仅在本次身份仍有效时清配置、释放已取得 token 并隐藏标记，不能清除后来建立的绑定。异常交调用入口报告，Unity 生命周期中的异常由 Unity 报告。OnEnable 重订失败采用同一收尾。
5. 测试消费者在主线程创建服务，向生产者和多个组件注入接口，用 `Shop`、`Shop.Gold` 等测试路径驱动自身值。结束时停止生产、解绑全部视图、销毁服务，`finally` 清理测试对象。换会话先结束旧实例再创建并绑定新实例；消费者以会话标识拒绝旧异步结果，不让其写入新服务。
6. 批量 Bind 先获取含 inactive 的有序组件快照并无副作用预校验，再逐项调用内部绑定路径。每项在开始订阅前记录本次操作身份，区分幂等未变与新建／替换；不能把 Subscribe 返回后回调已建立的新身份冒认为本次所有。订阅阶段失败按本章行为规则逐项清理并抛 `AggregateException`，包含原始及清理异常；Unbind 的快照同时记录当时身份，清理一个成员引发的其他重绑不得被旧快照清除，收尾错误统一以 `AggregateException` 汇总。
7. 两个 Prefab 使用同一 RedNotify，子标记默认隐藏、组件引用预接；圆点无 Text，数字 Text 预接，所有装饰 Graphic 关闭 raycastTarget。可复用参考资源层级，但需重接本工程脚本／资源引用，不残留旧工程专属 GUID、UIText 或 XAsset 依赖；字体、sprite 等来自工程内或可用 Unity 内置资源。此处只做既定 Prefab 适配，不全量搬运资产；具体美术可选，但必须导入无丢失引用并实际显示。

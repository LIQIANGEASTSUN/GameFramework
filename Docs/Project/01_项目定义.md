# 项目定义

在当前 GameFramework 工程中逐步完成一款可交付的游戏。用户决定产品方向和关键取舍，Agent 负责调查、方案、实现、修复与整合；验证分工见[Agent 协作协议](04_Agent协作协议.md)。

## 已确认的边界

- 在现有 Unity 工程上推进，保留已有实现与并发改动；“从 0”不表示清空仓库。
- 当前处于尚未出包的 Demo 阶段，没有已发布版本的设备标识兼容需求。
- Android 支持下限确定为 Android 8.0（API 26），不支持 Android 6/7；此技术支持边界不代表 Android 已被选为首发平台。
- 交付目标包含完整玩法、内容、运行验证与用户实际可获取的版本。
- 游戏类型、首发平台、内容规模和商业模式尚未确定；当前配置和技术建议不能代替产品决定。

## 需要确定的产品内容

| 内容 | 当前情况 | 直接影响 |
|---|---|---|
| 目标玩家、游戏类型、核心操作循环、一次体验的结果、首版可玩目标 | 待与用户确定 | 第一条玩家流程、玩法规则与验收 |
| 首发平台、设备、输入方式、画面方向、运行环境 | 待定 | 输入、UI、平台依赖与性能目标 |
| 美术和声音方向、可用资源、关卡或内容规模 | 待定 | 代表性内容、制作流程与质量目标 |
| 单机或在线；账号、商业化、广告、支付、分析和外部 SDK 是否进入首版 | 待定 | 数据、服务、离线策略与渠道交付 |

优先明确前两项。内容与服务随近期实际需要决定，性能、容量、数量和工期据此确定。能由代码、配置或定向验证回答的问题由 Agent 调查；需要用户选择的事项集中说明影响，不以猜测补成需求。

## 从第一条流程推进

1. 定义从启动、操作、获得结果到再次开始的完整体验，同时明确首发平台与操作方式。
2. 核查该流程实际需要的代码、场景、资源和环境，基于已有消费者决定复用与补齐范围。
3. 选择能够验证玩法的最小内容，将持续协作的需求与可执行工作项写入所属模块的功能文档，由 Agent 实现并接通完整流程。
4. 产出目标平台开发包，验证真实启动、操作与资源加载，再依据体验确定下一段内容和系统。

第一条流程可玩后，先判断核心体验是否成立，再逐步补齐代表目标质量的表现、进出、中断恢复和数据能力。需要保留进度时纳入保存与重启读取；不预先搭建尚无消费者的全套框架。

## 实际交付

交付前明确本次内容、平台、必要验证、已知限制和恢复方式，确认验收版本与交付版本一致，用户能够获取并安装或启动。渠道上架与外部账号操作按实际需要和授权执行，构建成功不等于已经发布。

产品答案更新本文；具体行为与验收由所属功能文档维护。近期协作见[近期工作](07_近期工作.md)，验证按[工程标准](05_工程实施与验收标准.md)执行。

# 架构与模块

本文维护本项目代码与资源归属、框架接入入口；独立包的职责、边界、依赖与接入约定由各包根 `README.md` 维护，不随功能扩展增加清单。

## 项目职责与目录

以下为归属约定，目录随实际需求建立。

| 位置 | 归属 |
|---|---|
| `Assets/Game/<模块>/` | 具体玩法、业务与数据规则、游戏资源、差异化实现，以及项目组合入口、配置与流程策略；模块代码与资源就近组织 |
| `Assets/Module/Red/` | 用户指定的红点系统模块根；本地契约、实现、视图与资料就近组织 |
| `Assets/Settings/` | 共享渲染配置 |
| `Assets/Scenes/` | 游戏场景 |

项目模块入口在本文维护，包内能力按包 README 的目录约定定位模块根，再从其 `Docs/` 中按功能文档的标题与范围选读；子模块通过已有父级导航或模块目录发现。执行进展查阅对应工作项的记录，既有“需求 + Tasks”仍从需求直接导航 Task。不建立空模块清单。

- [Red 红点系统](../../Assets/Module/Red/Docs/需求与实施.md)：前缀树计数、通知与视图绑定的需求、实施工作项及验证。

# 怎样查询、启动和继续工作

用自然语言说明要了解或完成什么即可。“任务”也可以是一项尚无文件或编号的具体工作。

## 跨项目复用

仅复制 `Docs/Project/` 时，先将其作为协作方法参考，不能把 GameFramework 的项目事实、功能文档、工作项或代码视为目标项目规范。应核查目标项目的真实代码、资源、输入与并发改动，校正[项目定义](01_项目定义.md)、[架构与模块](02_架构与模块.md)和[近期工作](07_近期工作.md)中的项目专属事实；逐条校对[协作协议](04_Agent协作协议.md)的 Unity 验证分工、[工程标准](05_工程实施与验收标准.md)的工程要求及[模块规范](08_模块组织与交付规范.md)的 Assets/包结构等规则，不适用处先讨论修正。

目标项目还须补齐或修正根 README、`AGENTS.md`、`Docs/Templates/`、实际模块的功能文档与工作项（默认 `Docs/需求与实施.md`；既有结构仍从 `Docs/需求.md` 直接导航 Task），并修复引用；不能仅凭复制的目录声称可查询任务。本项目的功能文档、工作项和代码只可参考写法与取舍。查询时按下文规则说明可直接实施、须先调查或讨论、受阻的具体依据、缺口与解除条件；规划工作项不等于实施授权。

## 可以直接这样说

| 意图 | 可以复制的问法 |
|---|---|
| 询问当前工作 | `当前可以执行哪些任务？请按推荐顺序列出，并说明依据和缺口。` |
| 指定模块 | `请看看 <模块名称> 当前有哪些工作能开始，哪些还缺输入。` |
| 选择刚列的一项 | `执行刚才列表中的第 2 项，完成适用检查与验证交接。` |
| 点名已有工作 | `请启动并完成 <名称或文档路径>。` |
| 提出新需求 | `请在 <模块或场景> 实现 <具体结果>，范围是 <边界>。` |
| 整理需求与规划 | `请整理 <目标> 的需求与实施工作项，暂不实现。` |
| 恢复工作 | `请继续完成刚才的工作，从上次停下的位置继续。` |
| 只讨论方案 | `先讨论 <目标> 的方案，说明取舍，暂不实现。` |

替换尖括号内容即可，无须先查询或领取编号。查询本身只读，不改代码、修文档或运行 Unity；它不撤销其他正在推进工作的既有授权。若要暂停，明确说“暂停当前实现，先只回答这个查询”。

## 查询回答应包含什么

项目级“当前有哪些任务”先从根 README 与[架构与模块](02_架构与模块.md)定位实际模块根；包内按包 README 的目录约定定位模块根，查看其 `Docs/` 下功能文档的标题与范围，子模块通过已有父级导航或模块目录发现。读取候选工作项的执行状态（新建默认在 `Docs/需求与实施.md`；既有结构从 `Docs/需求.md` 直接定位 Tasks），结合用户目标与[近期工作](07_近期工作.md)选择候选。包 README 不维护功能清单，不依赖包根需求或另建索引发现功能。点名范围时只读所选模块及直接依赖。随后只深入候选及直接依赖，核查代码、资源、输入和文件占用，不通读历史。部分未核查时明确范围，不能据局部检查判断全项目无任务；模板例子也不自动成为需求。

回答先说明已核查范围与未知项，再列少量候选，每项说明推荐依据。下面仅为回答结构，不是当前任务库存：

```text
已核查：<目标、模块与直接输入；尚未核查的限制>
建议先做：<名称与依据>
1. <工作名称>：<具体交付结果与边界；推荐依据>
   可做阶段：<直接实施 / 先调查或设计 / 从哪个位置恢复 / 受阻部分>
   输入与缺口：<实际产物；缺什么、影响哪段、如何解除>
   并行限制：<共享文件、资源或执行环境；正在执行者或待交接情况>
   承接位置：<已有功能文档及工作项链接，或当前会话承接>
```

阶段是本轮查询判断，不新建或改写工作项状态，也不保存查询快照。按当前目标、可用输入与交接情况判断；可从可消费的部分开始，新源码或资源也可以是本次授权产物，不因缺文件或 ID 自动阻塞。未知处给下一步核查；玩法和平台未定时先对齐或调查，不能宣称完整游戏已具备实施条件。

## 选择、启动与恢复

收到“执行第 N 项”后，Agent 绑定原列表的名称、目标与范围，简述后复查输入并继续。编号只用于该次列表；映射丢失或目标含糊才澄清，不能用新列表的同号替换原目标。也可直接点名或描述新需求。

已完成、已取消或已替代项不列为新启动工作；新要求先定位新增或未完成范围。已有人推进时说明执行者或待交接情况，交接前不重复派写。

这是默认查询规则；用户明确要求依据同一版功能规范重新实现或比较多套实现时，不因 `Done` 拒绝。按[文档规范](06_文档组织规范.md#可独立实施的文档)复用共同依据，按[协作协议](04_Agent协作协议.md#授权范围与协作)隔离执行并分别验证，不能将一套结果视为其他实现通过。

“只讨论/只调查”停在约定阶段；“启动并完成”按[Agent 协作协议](04_Agent协作协议.md)分工推进实现与验收，解除阻塞后自动续行。读取适用的包 README 框架规范后，持久协作从功能文档定位相关工作项，依其执行记录核查当前前置缺口、验证结果与下一步；未迁移的既有模块仍从需求直接导航 Task，职责见[模块规范](08_模块组织与交付规范.md)。

项目入口见根 [README](../../README.md)。

# Agent 协作协议

每项工作都由主 Agent 与负责该项的实现或评审 Agent 对齐方案，交实现 Agent 落地，再由未负责该产物实现的主 Agent 或另一 Agent 独立检查。小修也遵循这条协作链，可在会话/PR 完成，不要求三个不同 Agent 或新增文档。

查询、编号选择和只读边界执行[任务使用指南](03_任务使用指南.md)；文档职责与状态位置见[文档组织规范](06_文档组织规范.md)，工程质量要求见[工程标准](05_工程实施与验收标准.md)。

## 从要求到可执行计划

1. 读取本次用户要求、相关需求/验收、Task、源码 README 和实际输入，只覆盖本次范围与直接依赖。
2. 区分用户已确认要求、Agent 建议和源码事实。若代码与需求不同，先判断是事实过期、需求已变还是实现偏离；不能直接按代码降低目标，或把旧文档当成当前实现。
3. 主 Agent 与负责 Agent 对齐可供分派的方案：交付与非目标、可消费输入、实际文件、接线位置、资源/状态归属、必要验证及关键取舍。未决定的产品或公共契约选择明确留待决定，不藏在实施步骤里。
4. 长周期工作按可独立交付、可验证的产物分成步骤或 Tasks，写清每段输出和消费者。最终集成者负责把各段接到真实入口并核对联合验收结果；各子任务完成不等于功能已经接通。

委派取上述计划中该项必要内容。具体产物可用即可开展消费方工作，无须等待提供方整项完成；已授权的小修不因缺文档或编号停止。

区分当前阶段的前置与本次产物：新源码、资源或测试夹具可在授权范围内建立。仅缺最终验证环境或用户反馈时，可继续不依赖它的已授权部分；这不代表整项完成，必要验证仍约束最终交付。

## 授权、范围与协作

自然语言要求启动、修复、完成或继续，覆盖已说明范围的方案、实现、必要验证、修复与交付。用户只要求调查/方案时尊重止点；回答解除阻塞后自动续行，不重复询问已决定事项。

尚未确定的玩法、平台、商业规则、重要契约变化或需要授权的外部操作，先完成不依赖答案的核查与可审阅准备，再集中说明必要选项及影响。长期完成游戏的目标不代替具体产品决定。

只并行输入稳定、输出可独立交付的工作。同一文件指定一个写入者，共享执行环境与输出不得相互覆盖。保留用户及其他 Agent 的改动，无关工作区变化不阻断独立工作；只改约定范围及完成它必需的最小相邻内容。

分支、提交、合并、远端和发布操作按当时授权及工具权限执行，不用重置或清理丢弃现有工作。

## 实施、接入与偏差

实现者按计划小步完成，先使一个可观察结果接到真实消费者，再扩展下一段；临时方案注明替代产物和退役条件。发现问题按实际影响处理：

| 发现 | 动作 |
|---|---|
| 路径、名称或已观察事实过期 | 核查并修正所属正文，继续 |
| 步骤不可行，目标与公共契约不变 | 与负责 Agent 对齐最小调整，在原任务或会话简记原因 |
| 改变已确认行为、归属、公共契约、兼容或验收 | 暂停受影响部分，核对已有决定与授权；仍有重要取舍时由用户决定，再更新相关需求与计划 |
| 必需输入或环境无法取得 | 说明受影响结果、已知事实、无法绕过的原因和解除条件，继续不受影响的部分 |
| 与本次交付无关 | 有后续价值时记在所属已有工作或交付说明，不顺手扩大实现 |

## 验证与独立检查

默认由用户执行 Unity 启动、导入、编译、运行测试和构建；Agent 负责实现、静态检查、必要测试代码、验证步骤与预期结果，并依据反馈修复。后续用户明确委托且工具可用时，按当次授权执行，不为已确定的分工重复请求确认。

实施前确定哪些验证是**必要**的；条件验证写明“触发条件 → 方法”，触发后纳入完成判断；可选验证仅提供额外信心。依据[工程标准](05_工程实施与验收标准.md)结合本次风险确定检查，无须为三类各建一张空表。新事实暴露风险时补对应验证，已有结果仍适用则复用。

必要项或已触发的条件项失败、未执行、未选中目标用例时，不能将整项标为 Done 或宣称验收通过；必要 Unity 验证未执行时，在已有进展或结果中标明“待用户验证”。用户反馈须对应本次交付及必要场景，不能用无关旧结果代替。用户明确豁免或接受等效替代时，简记真实授权、原项情况、替代依据与限制，再按调整后的约定判断，不冒充原验证通过。

验证对象不明确、重试没有新事实或修复验证设施开始扩大范围时，停止该通道并说明结论与缺口；判断现有结果是否足以覆盖目标。已完成的代码可先独立检查；必要验证与最终独立检查均满足后完成整项，不反复扩大测试。

独立检查者对照需求、实际接线、资源/状态归属、失败终态、修改范围和验证结果审查最终产物。问题交实现 Agent 修正，再检查受影响部分；最终集成者核对联合行为的验证结果，不用子任务结论替代。

## 交付与恢复

交付说明实际改动、接收方与使用入口、验证方法和结果、独立审查意见处理及剩余限制。文档回写与状态按[文档组织规范](06_文档组织规范.md)处理。

中断时在当前 Task 或会话留当前交付点、下一步、阻塞条件和已交接写入者。恢复时对照需求/验收、相关代码与输入变化，明确哪些结果可复用、哪些需要重做，再从有效位置继续；已完成任务不默认重开。

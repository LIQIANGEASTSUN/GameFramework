# 怎样查询、启动和继续工作

用自然语言说明要了解或完成什么即可。“任务”也可以是一项尚无文件或编号的具体工作。

## 可以直接这样说

| 意图 | 可以复制的问法 |
|---|---|
| 询问当前工作 | `当前可以执行哪些任务？请按推荐顺序列出，并说明依据和缺口。` |
| 指定模块 | `请看看 <模块名称> 当前有哪些工作能开始，哪些还缺输入。` |
| 选择刚列的一项 | `执行刚才列表中的第 2 项，并完成必要验证。` |
| 点名已有工作 | `请启动并完成 <名称或文档路径>。` |
| 提出新需求 | `请在 <模块或场景> 实现 <具体结果>，范围是 <边界>。` |
| 整理需求与规划 | `请整理 <目标> 的需求并规划 Tasks，暂不实现。` |
| 恢复工作 | `请继续完成刚才的工作，从上次停下的位置继续。` |
| 只讨论方案 | `先讨论 <目标> 的方案，说明取舍，暂不实现。` |

替换尖括号内容即可，无须先查询或领取编号。查询本身只读，不改代码、修文档或运行 Unity；它不撤销其他正在推进工作的既有授权。若要暂停，明确说“暂停当前实现，先只回答这个查询”。

## 查询回答应包含什么

项目级“当前有哪些任务”先轻量发现 `Modules/` 各模块、子功能入口及未完 Task，再结合用户目标与[近期工作](08_近期工作.md)选择候选；指定范围时只在该范围查找。随后只深入候选及直接依赖，核查代码、资源、输入和文件占用，不通读历史。部分未核查时明确范围，不能据局部检查判断全项目无任务；模板例子也不自动成为需求。

回答先说明已核查范围与未知项，再列少量候选，每项说明推荐依据。下面仅为回答结构，不是当前任务库存：

```text
已核查：<目标、模块与直接输入；尚未核查的限制>
建议先做：<名称与依据>
1. <工作名称>：<具体交付结果与边界；推荐依据>
   可做阶段：<直接实施 / 先调查或设计 / 从哪个位置恢复 / 受阻部分>
   输入与缺口：<实际产物；缺什么、影响哪段、如何解除>
   并行限制：<共享文件、资源或执行环境；正在执行者或待交接情况>
   承接位置：<已有需求/Task链接，或当前会话承接>
```

阶段是本轮判断，不新建状态或保存查询快照。按当前阶段所需目标、输入与写入归属判断，不等待上游整体 Done；新源码或资源可以是本次授权产物，当前为空不等于无法从 0 实现。未知处给下一步核查；玩法和平台未定时可先对齐或调查，不能宣称完整游戏已具备实施条件。没有任务文件或 ID 本身不构成阻塞。

## 选择、启动与恢复

收到“执行第 N 项”后，Agent 绑定原列表的名称、目标与范围，简述后复查输入并继续。编号只用于该次列表；映射丢失或目标含糊才澄清，不能用新列表的同号替换原目标。也可直接点名或描述新需求。

已完成、已取消或已替代项不列为新启动工作；新要求先定位新增或未完成范围。恢复工作检查当前进度、输入变化和仍适用的结果；已有人推进时说明执行者或待交接情况，交接前不重复派写。多个工作并行前核对真实写入与执行环境冲突，共享文件有唯一写入者。

“只讨论/只调查”停在约定阶段；“启动并完成”按[Agent 协作协议](05_Agent协作协议.md)完成方案对齐、实现接入、必要验证和独立检查。用户回答解除阻塞后自动续行，不再索要启动口令。小修由会话/PR 承接，持久协作按[文档组织规范](07_文档组织规范.md)定位模块需求与相邻 Tasks。

项目入口见根 [README](../../README.md)。

# 工程实施与验收标准

本标准按实际改动与风险适用；职责与依赖见[架构与模块](02_架构与模块.md)，协作与验收分工见[协作协议](04_Agent协作协议.md)，文档维护见[文档组织规范](06_文档组织规范.md)。

## 1. 需求与依据

- 以需求、Task 及其显式规范依赖确定实现与验收要求，区分实际产物、待实现与待定要求；源码和测试用于核对是否符合，不能反向定义标准。规范纠错按[文档组织规范](06_文档组织规范.md#后续修改与当前结论)处理。
- 源码、资源、配置和依赖须有权威来源，生成结果与其一致；不得用缓存或构建产物证明或补造源实现。

## 2. 代码与设计

- 保证正确性，保持结构简洁、易读易懂、易于扩展，明确职责、命名和数据语义；同一规则集中维护，避免冗余、假想抽象与不必要复杂度。
- 遵守单一职责、开闭、里氏替换、依赖倒置、接口隔离、迪米特（最少知识）六大原则及常见设计模式规范；模式按实际需求选用。
- 遵循项目架构，契约隔离实现细节，消费者按模块明确的公开契约与接入形式使用能力；通用能力默认面向接口，已确定的直接 API 按约定使用，不为此另造无用接口。组装与作用域明确，禁止循环和隐式依赖，包依赖与程序集引用分别正确，限制变化对无关消费者的影响。
- 核心规则可独立验证，数据写入责任清楚，副作用和失败显式表达，不吞错或伪造成功。

## 3. 生命周期

- 明确所有权及生命周期的主责任方、起止边界、推进与清理责任，限定合法状态与调用语义；共享和复用须明确有效期、保持状态隔离，所有权转移须显式。
- 正常、失败、中断、取消和重复操作均应有可控结果，重复收尾安全。部分初始化中止也须清理，先结束使用方再释放依赖资源；单步清理失败不得遗漏其余释放。
- 退出时停止不再需要的工作，无法立即停止时隔离其结果；失效工作不得污染新使用或覆盖有效结果。终态、资源和副作用可观察，业务回滚或补偿须有需求依据。

## 4. 兼容与交付

- 保持约定的输入、结果、时序、失败语义及契约、数据、资源身份兼容；变化须有需求依据、明确影响范围和迁移结果。
- 源码、资源、元数据、配置与依赖须完整有效；本次范围包含业务集成时，须接通约定的真实消费者。删除或替换不得遗留失效入口，临时方案退役须以替代成立为前提。
- 源码、资源及必要验证内容随所属仓库交付，明确未提交范围；主项目引用的子模块版本须对应实际交付，需要远端交付的版本须可获取。

## 5. 验证与验收

- 按规范依据与本次风险审查设计质量，验证约定范围内的行为与边界，明确可判定的预期结果，不用复述实现代替行为验证。独立基础库可用调用真实实现公开入口的最小消费者或测试验证，文档任务按文档验收，不自动新增业务接线；已约定的业务集成仍须完成，不能以局部测试代替。多套实现各自对照同一规范验收。
- 每帧执行、缓存和性能容量方案按实际需求与目标环境评估，在可比条件下测量相关成本。
- 编译、逻辑、集成、平台和发布结论不得越级代用。必要验证未完成不得宣称通过，不得降低要求或隐瞒失败。
- 验证对应最终交付，区分通过、失败、未执行、跳过和未覆盖；保留可复现入口及必要输入依赖，只复用仍有效的结果，只重做受影响检查。

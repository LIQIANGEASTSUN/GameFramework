# 工程实施与验收标准

按本次改动触发相关条目；验证范围和收口由[协作协议](05_Agent协作协议.md)决定，结果存放按[文档组织规范](07_文档组织规范.md)处理。工程现状见[02](02_工程现状.md)，代码归属见[03](03_架构与模块.md)。

## 1. 输入、替换与实际接入

**触发：** 修改源码、资源、配置，或替换已有实现。

- 在主仓检查 `git status --short`，涉及子模块再检查对应工作区，保留并发修改。以真实源码、asmdef/asmref、Prefab 与配置判断输入，不从生成项目文件或历史通过记录推断能力存在。
- 替换实现前核对实际调用分支、参数含义、状态变化、时序与失败语义，区分本次改变和必须保留的行为，必要时用定向用例固定原行为。按真实职责逐项映射，不把相似类名视为等价。
- 实施步骤包含消费者、场景、配置与资源接线。共享能力和业务接入可分段交付，最终集成者验证真实入口到联合结果；单独类或接口可编译不代表已经接通。
- 测试暴露差异时先判定需求、实现或夹具哪处有问题。开发期资源/配置错误由实际引用与加载检查发现，不通过扩大共享框架兜底、删除断言或改变正确产品行为让测试通过。

**完成判据：** 能定位输入、改动、消费方与实际结果；保留行为成立，替换后的入口和依赖已接通。

## 2. 子模块与程序集交付

**触发：** 修改独立包、asmdef/asmref 或公共依赖。

- 包内代码、资产、测试和 `.meta` 属于其子模块；检查包内 diff，主仓核对 `git diff --submodule=log` 与 `git submodule status`。
- package.json 负责包可解析，asmdef 负责程序集引用；验证真实消费者，不倒置 Runtime/Editor 依赖或手改生成 csproj 解决源码问题。
- 获授权提交时先提交相关子模块，再由主仓记录正确指针；跨包交付明确实际版本，需要远端交付时确认提交可获取。仅交付工作区修改时说明哪些包未提交。

**完成判据：** 源码、资产、meta 与依赖齐全，受影响程序集及消费者验证成立；主仓 commit 不冒充子模块未提交文件已交付。

## 3. Unity 目标与执行环境

**触发：** 准备启动 Unity、导入、编译或测试。

1. 读取 `ProjectSettings/ProjectVersion.txt` 并选择对应 Editor。通过主进程可执行文件、PID、`-projectPath` 或已连接 Editor 的项目路径确定目标，排除 `AssetImportWorker`；只取定位字段，避免保存含登录参数的完整命令。
2. 工程已打开时使用该实例的验证入口，或本次专属隔离项目；不对同一路径另起 batchmode，不关闭其他工作所属 Editor。编辑源码不因 Editor 打开自动受阻。
3. 程序集变化导致 `.csproj/.sln` 过期时，由 Unity/IDE 重生成；不补造不存在源码迁就生成物。
4. 同一测试工程、构建目录和输出只由一个执行者写入，结果使用专属临时路径。

**完成判据：** 工程、版本、程序集与本次结果对应，未误用其他实例、过期生成物或旧日志。

## 4. 生命周期、输入与异步请求

**触发：** 改变创建/关闭、资源订阅、输入归属、请求或 View 接入。

- 对每条创建路径明确持有者与释放责任，初始化失败清理已创建部分，重复关闭不重复通知。专用宿主可整体释放，共享宿主按实际组件边界处理。
- Unity 对象 API 在主线程使用；关闭时退订事件、停止 Timer/Tween/Coroutine 或取消请求。迟到回调先判断 owner/请求仍有效；只在实际需要区分旧实例或请求时增加身份标识。
- 改变输入接线时，明确交互域内的活动来源及每次手势的消费方。切源先取消旧交互再发布新来源；遮挡、失焦、禁用或销毁不能泄漏输入，也不误恢复应停用的旧来源。用真实 EventSystem/组件验证涉及的交接和中断路径，不强行限制无冲突的多路输入。
- 涉及异步或 View 就绪时，说明可观察的就绪条件、取消/替代或排队策略。发出事件、等待固定时长不等于完成；已接纳请求各有且仅有一次终态，被取消或替代的请求不再提交过期状态。
- 区分业务结果与表现完成：已提交业务不因动画取消丢失或重复。表现失败是否影响尚未提交的业务由需求决定，不能吞掉业务终态。

**完成判据：** 改变的正常、失败、取消、销毁与再次进入路径成立，无双清理、双通知、旧回调写入或错误消费；未涉及的机制不额外设计。

## 5. 资源、序列化与迁移

**触发：** 新建、移动、重命名、删除资产，或改变数据与资源加载。

| 改动 | 实际动作与通过条件 |
|---|---|
| 新建/复制资产 | 生成独立 meta/GUID，检查脚本、字体、材质、图片等依赖；真实加载无 Missing Script，组件和引用正确 |
| 移动/重命名资产 | 资产与 meta 成对移动并保留 GUID；更新路径、动态键及消费者，验证新入口与所需兼容 |
| 删除资产或临时补丁 | 明确替代产物与退役条件，消费者已切换，必要替代行为通过，再检查残余路径/GUID引用 |
| 重命名字段、枚举或数据键 | 核对 Prefab、场景、存档与协议消费者，保留身份/数值含义或实施明确迁移；已有数据能按约定读取 |
| 修改生成配置 | 找到权威源与真实生成命令，改源后生成并验证消费；没有生成链就说明直接编辑源 |
| 动态资源与发布包 | 配置实际加载/收集入口并在目标包验证，编辑器引用正确不能替代打包后可加载 |

GUID 文本存在不证明资源可用，用 `AssetDatabase` 实际解析或运行加载检查。Prefab/场景与动态资源均核对实际依赖；Library、obj、构建输出和生成项目文件不作为人工业务源。

## 6. 按改动选择验证

| 实际风险 | 要证明的结果 |
|---|---|
| 文档、注释、排版 | 相关内容、链接与 diff 正确；不启动 Unity |
| C# 规则变化 | 所属程序集编译，改变的规则有意义的定向用例成立；不写镜像实现的测试 |
| Unity 生命周期、输入、场景或 UI | 真实组件/资产的定向 EditMode/PlayMode 正常与中断行为成立；用户可见变化核对画面和交互 |
| 资产绑定、资源加载、公开 API/依赖 | 实际引用与消费方通过；动态资源按其真实加载链验证 |
| Player/平台 API、AOT/裁剪或设备差异 | 在对应 Player/设备验证实际风险，Editor 结果不代替 |
| 热路径工作量、分配或布局刷新有回归风险 | 同条件比较改变前后的相关耗时、分配或重建次数；检查无变化时不重复刷新、关闭重进后资源/订阅回到预期 |

性能验证由实际风险触发，不因方法叫 Update 就自动增设门槛；目标随真实平台与需求确定，不预设统一帧率或零分配。必要项与已触发条件项通过后进入审查，额外测试按新风险决定。

## 7. 可复跑测试与完成判据

测试源码跟随模块，Editor-only 逻辑和工具限定 Editor；实际挂载的 MonoBehaviour 夹具来自可挂载程序集。Editor 测试可以进入 Play Mode，执行平台标签不能单独证明场景生命周期已经覆盖。

长期回归保存必要的夹具源码或生成器、版本/依赖与运行方式，并在现有模块 README 给出测试入口。临时工程需要能重建，旧 XML 或命令本身不能重建缺失的环境。

下面仅是参数结构，执行前替换为实际 Editor、已准备好的隔离工程与目标程序集：

```sh
"<对应版本 Unity 可执行文件>" \
  -batchmode -nographics \
  -projectPath "<本次隔离工程绝对路径>" \
  -runTests -testPlatform EditMode \
  -assemblyNames "<实际测试程序集名称>" \
  -testResults "<本次临时结果文件.xml>" \
  -logFile "<本次临时日志文件.log>"
```

隔离工程引用实际待测包和 Test Framework；消费包测试时，manifest 的 `testables` 包含实际包名。多程序集以分号分隔并整体引用，按真实用例选择对应测试平台和过滤器。

核对本次输出的程序集、用例、执行时间、通过/失败/跳过数及日志；`0 tests`、只编译或旧结果都不是通过。结果对应最终交付的源码与资源，后续变化只重验受影响范围。编译、逻辑、组件场景、Player、设备和实际发布分别说明，不能互相冒充。

# 文档组织规范

功能文档的规范正文及其显式引用的规范依赖，是目标、接口、行为和验收的唯一规范依据。本文称同时承载需求、必要方案、实施工作项与验证的文档为“功能文档”，默认命名为“需求与实施”。工作项（Task）是可分派、跟踪和验收的交付单位，不必独占文件；执行状态与结果另记，不反向改变规范。源码、测试与运行结果用于核对实际实现是否符合文档。

## 按功能边界组织文档

默认每个功能模块使用一份完整文档，承载目标与边界、行为与接口、必要设计、实施工作项、验证方法与预期，并分开记录执行结果。明确具备稳定职责与契约、可以独立交付和验收的功能，可分别成文；紧密关联、难以独立说明的内容放在同一文档中，以多个工作项分别推进。

拆分依据是长期功能边界，不是需求、设计、实现、测试等阶段，也不是临时 Agent 分派、仅能并行实施或篇幅较长。独立不等于零依赖：各文档应清楚定义自身范围，通过明确链接消费共有契约和依赖；不把一项功能的规则拆成需要依次拼读的顺序文档，不复制共有规则。拆分文档不要求同步拆分模块、仓库、程序集或迁移代码目录。

较大文档优先按能力分章，将该能力的行为、接口、必要方案和验证就近组织；简单内容可合并章节。每条规则只完整定义一次，工作项引用相关章节，不再复述一套需求或设计。可观察的验收结果与可执行的验证方法承担不同职责，不能为了去重删去必要方法。按读者目标选用内容，不机械填满模板，也不把核查过程逐项写入正文。

独立包根 README 简洁维护包级稳定职责、边界、依赖、程序集、组合使用与文档组织约定，仅随这些规则变化而修改，不登记功能清单、API 或执行状态，不另建包根需求。功能文档须显式引用适用的包 README 及其他规范依赖。功能模块不另设 README 或替代说明层；已有上层入口与模块目录约定负责发现文档，具体路径见[模块规范](08_模块组织与交付规范.md#2-入口与工作资料)。项目根 README 与项目文档导航不能取代功能规则。

## 可独立实施的文档

无论实现前后，任何 Agent 都应仅凭功能文档及其显式规范依赖取得完整的实现与验收规则，独立完成或重新完成实现、接通与验收。不得依赖本次源码、测试、会话或历史差异补齐关键规则；资源等实际输入可由文档定位，但不能代替行为说明。

- 明确目标、可观察行为、边界和验收结果，落定影响实现的接口、状态与资源归属、必要执行顺序、失败终态及验证方法与预期。已有规范契约可显式链接，包 README 提供框架约束，不能用实现说明或源码代替缺失的功能规则。
- 多个 Agent 可以依据同一版文档分别产出多套实现。文档约束共同目标与必要方案，用户明确指定的实现约束须保留；未约定的普通代码细节由实现者决定，不把某套实现的选择自动提升为公共要求。
- Agent 在授权目标内解决常规工程选择，记录交接所需结论，不转为用户待确认问题。确有缺失的产品决定、重要公共契约变更或必需输入时，说明影响与解除条件；受影响部分不能宣称已可独立执行。

## 规范正文与执行记录

目标、方案、接口、行为、实施工作项约定及验收正文默认保持不变。执行及完成时只常规更新状态与结果；正文修订须满足[后续修改规则](#后续修改与当前结论)，不能从“执行任务”推导出用户另行授权修订正文。不得因实现完成、状态变为 `Done` 或代码既成事实而改写、压缩正文，用结果替换方案，或迁到实现说明中。精简、去重和整理不能作为执行中自行改正文的理由，也不能把正文换成源码、测试或实现说明的链接。

规范正文写清稳定的输入、就绪规则、工作项产物及依赖；执行记录与结果写明当前是否满足、实际产物、状态、验证结果、必要交接与下一步。二者可在同一文件中，语义和章节应可区分。状态按工作项和具体实现唯一维护，详见[工作项分工](08_模块组织与交付规范.md#3-工作项分工与交付状态)。实际源码与测试入口在对应章节导航，不另复制现状 API 为另一份契约。

同一文档指定一个写入者统一维护，各实现者仍可并行修改各自获分配的代码和测试；以交接提供结果，不争写共享文档，不为解决写入冲突而人为拆分规范。

## 目录与入口

根 [README](../../README.md)是项目工作入口，`AGENTS.md` 是 Agent 执行入口。项目级 `Docs/` 使用以下目录，根目录不放 Markdown 正文或重复 README：

- `Project/`：项目说明、使用指南与通用规范。采用连续两位数 `NN_名称.md`；新增接末尾，删除/合并后整理后续编号并更新入向链接，不预留空编号。编号仅用于阅读排序，按需读取。
- `Templates/`：功能文档的按需填写结构，不使用 Project 的编号。

模块资料按[模块规范](08_模块组织与交付规范.md)放在模块根。既有资料变更位置前核查归属与引用，不自动迁移或删除。

## 创建、拆合与退役

| 情况 | 动作 |
|---|---|
| 可在当前会话完成的小修 | 沿用已有规范依据；实际文档问题先按后续修改规则讨论修正，执行结果可在会话或已有 PR 承接，不强制先迁移文档 |
| 长周期、跨会话或多人协作的真实需求 | 使用[需求与实施模板](../Templates/需求与实施.md)，按功能边界就近建立完整文档与工作项 |
| 已有模块继续迭代 | 回到原文档，续做范围相符的未完工作项；新增独立交付可增工作项，符合功能拆分边界时才另成文档 |
| 功能需要拆合 | 依据本文的功能边界规则与模块规范，明确每份文档范围，保全规则、工作项及结果并修正引用 |
| 多处反复维护同一规则 | 不据此在执行中自行修改正文；实际问题按后续修改规则处理，另有明确文档修订授权时在授权范围内去重，保全必要语义与独立重新实现依据 |
| 需要工作入口或 API 接入说明 | 就近写入功能文档的范围、行为、接口与用法章节，不另建功能模块 README 或说明层 |
| 工作项完成 | 保留规范正文，更新对应状态及必要结果；完成不代表文档失去用途 |
| 用户取消或替代工作项 | 在原工作项记录“已取消”或“已替代”，简记用户决定、交付范围及替代入口，保留必要依据和已有结果并退出活动导航，不以 Done 冒充交付 |
| 用户明确退役文档 | 按真实退役范围处理并修正引用；不根据 Done、无人引用或已有实现自行推断可删除 |

用户授权规划真实目标时，可建立 `NotStarted` 工作项，写清实施方案及必要输入与依赖；也可仅讨论需求。规划不等于实施授权，不为假想目标预造工作项。不预填角色或结果占位，开工时明确实现者、评审者与唯一写入者。文件名表达稳定功能职责，不带阶段序号、临时 Agent 名或状态；工作项名称表达具体交付，需要引用时才使用稳定的局部标题、AC 或 ID，已有 GF 标识可保留。

## 既有文档的渐进调整

现有 `Docs/需求.md + Docs/Tasks/<具体交付>.md` 继续有效；需求与直接导航的 Task 中的规范正文及其显式规范依赖共同构成原有完整依据。新版规范不触发批量迁移，也不要求每次功能小修先调整结构。在用户授权的相关文档整理范围内渐进迁移，不同时维护新旧两套权威正文。

实际迁移时逐项核对原有目标、行为、接口、必要设计、失败与生命周期边界、验证方法和预期，以及工作项状态、有效结果、未解决问题和交接信息。将其映射到新的归属，修复所有受影响的入向链接和必要章节锚点，检查单项交付及联合验收责任未丢失。不能只拼接文件，也不能借合并丢掉必要规则、方法或证据；源码和测试引用仍只负责定位产物。

## 后续修改与当前结论

用户最新明确决定优先于尚未同步的旧文档，先回写必要规范再实施。项目规范规定共同规则；功能文档在此基础上定义需求、必要设计、实施与验收，工作项不得擅自缩减需求。正文修订仅因有证据的实际问题启动，或由用户另行明确改变需求、授权文档修订；普通执行授权不包含为省事、精简或去重而修改正文。

执行前或过程中，若已确认的项目演进使旧假设或依赖失效，或条款自相矛盾、会导致 bug、确实无法实现等，应核实具体问题。项目现状与文档不符不等于文档有错；若属于实现偏差或尚未完成，应修正实现，不反向修改标准。

确认文档有实际问题后，先暂停依赖问题条款的实现，说明具体条款、事实依据、影响与修正建议，回到所属规范正文讨论对齐；只修必要相关条款并同步关联规范，再依据修订版本继续。不受影响的部分可继续。常规纠错在已有授权内由主 Agent、实现 Agent 与独立评审讨论，不暗中改需求，也不增加逐次用户审批；尚未决定的产品或重要公共契约取舍仍由用户按[协作协议](04_Agent协作协议.md)决定。

迭代后正文应完整表达当前规范，不靠历次执行记录或追加补丁拼出有效规则。用户改变需求或验收时，核对关联工作项并更新受影响的规范依据，明确哪些工作项、实现与旧结果受影响；旧 Done 与历史结果不覆盖新要求。同一版文档供多套实现使用时，不能只适配其中一套。保留必要决定与纠错说明即可，不另建历史副本或全局台账。

## 结果与保留边界

执行记录简记当前交付点、验证方法和结果、独立检查、限制及下一步，按工作项和具体实现分别维护；保留仍有效的证据、未决问题、关键决定和恢复信息，不机械累积过程流水。历史结果标明适用范围，不能冒充当前结论。已授权小修可在会话或已有 PR 承接，不机械新增文档。长期回归保留测试源码、配置与可重现命令，运行日志和 XML 留工具临时输出或 CI；这些结果不替代规范正文。

不创建独立 Evidence、验证 README、测试/发布报告、来源哈希、历史归档或变相副本，也不把原始输出全文搬进既有正文。发布、疑难问题与文档整理使用同一规则；清理报告不删除测试源码和命令。外部项目仅供参考，适用结论写入当前规则，不复制来源文档或生成阅读记录、治理流水与全局台账。

# 文档组织规范

文档保存后续使用和协作必需的信息；每类事实在一个位置维护，其他位置按需链接。

## 目录与入口

根 [README](../../README.md)是项目工作入口，`AGENTS.md` 是 Agent 执行入口。Docs 分三类，根目录不放 Markdown 正文或重复 README：

- `Project/`：项目说明、使用指南与通用规范。采用连续两位数 `NN_名称.md`；新增接末尾，删除/合并后整理后续编号并更新入向链接，不预留空编号。编号仅用于阅读排序，按需读取。
- `Modules/`：按业务或能力职责集中需求与相邻 Tasks，可递归拆分独立子功能；不要求对应代码包层级。
- `Templates/`：需求、实施任务与源码旁模块说明的填写结构，不使用 Project 的编号。

| 代码职责、依赖方向、模块入口 | [02 架构与模块](02_架构与模块.md) | 边界整合者；定位归属时读 |

| Agent 分工、授权、偏差与交付流程 | [04 协作协议](04_Agent协作协议.md) | 协作方式维护者；首次使用或规则变化时读适用部分 |
| 工程质量要求与验收判据 | [05 工程标准](05_工程实施与验收标准.md) | 工程标准维护者；按实际改动读取相关要求 |
| 文档职责、目录、拆合与结果存放 | 本文 | 文档维护者；需要创建或调整文档时读 |
| 近期关注与实际依赖入口 | [07 近期工作](07_近期工作.md) | 主 Agent / 集成者；定位近期工作时读 |
| 目标情境、行为规则、边界与验收 | 所属模块 `需求.md` | 需求对齐负责人；修改该功能或消费其约束时读 |
| 单次输入、方案、接线、进度和验证结果 | 需求旁 `Tasks/<具体交付>.md` | 任务实现/集成者；执行与恢复该任务时读 |
| 实际 API、配置、生命周期与测试入口 | 源码旁已有模块 README | 改变 API 的实现者；接入或修改模块时读 |

Task 引用需求和验收，不复制背景；需求导航已规划的未完工作及仍影响接入/兼容的必要 Task，不枚举全部历史或复制任务状态。

## 模块内怎样归组

以下仅是结构示例，不表示已确定这些业务，也不创建空目录：

```text
Docs/Modules/
  活动/
    需求.md                  # 有实际内容才建立共有规则
    Tasks/接入活动入口.md
    礼包/
      需求.md                # 引用活动共有规则，维护独立行为与验收
      Tasks/实现领取流程.md
  商店/
    需求.md
    Tasks/实现商品展示.md
```

跨模块功能由一个负责最终结果的模块持有联合需求和验收，其他模块引用它，在各自相邻 Tasks 安排独立交付；最终集成者在具体任务中明确。父子需求不互抄，源码 API 也不另复制到 Docs。无需每层 README 或全局功能/任务索引。

## 创建、拆合与退役

| 情况 | 动作 |
|---|---|
| 可在当前会话完成的小修 | 会话/已有 PR 承接方案与结果，只更新确实变化的既有正文 |
| 长周期、跨会话或多人协作的真实需求 | 使用[需求模板](../Templates/需求文档.md)与[任务模板](../Templates/实施任务.md)，在所属模块组织需求和相邻工作单 |
| 已有模块继续迭代 | 回到原需求，续做范围相符的未完 Task；新增独立交付才就近拆 Task |
| 子功能有独立行为、读者、生命周期或 owner | 在大模块内拆子目录，需求与相关 Tasks 一起移动并修正链接 |
| 多份说明反复维护同一事实 | 合并有效独有内容到所属正文，修正引用后删除重复部分 |
| 当前 API 需要长期接入说明 | 按[模块模板](../Templates/模块上下文.md)更新源码旁 README，独立包的说明不依赖宿主 Docs 才能理解 |
| 任务完成 | 记录实际结果并只回写变化的需求/API/模块说明，移除无持续价值的近期与需求导航 |
| 任务取消或被替代 | 在原任务写“已取消”或“已替代”，简记原因、已交付/未交付范围及实际替代入口，保留已有结果并退出活动导航，不以 Done 冒充交付 |
| 文档或任务失去用途 | 有用知识先落回需求/源码 README；无独有交付或兼容依据且无人引用时可清理，有价值则原地保留，不按日期自动归档 |

用户授权规划真实目标时，即可形成 `NotStarted` Task，如实写明待决输入、未满足依赖与待分配角色；也可只讨论需求而不建 Task。规划文档本身不授权代码实施，是否执行看已有授权与当前止点。不为没有真实目标的设想预造任务。文件名表达职责或具体交付，不带临时 Agent 名/状态；需要引用时才使用局部 AC 或 ID，已有 GF 标识可保留。

## 后续修改与当前结论

需求或验收变化时，核对关联 Task 的适用范围；旧 Done 与历史结果不覆盖新要求。Task 用对应需求段落、当次范围或必要的已有 Git 版本说明依据，按真实新增范围调整未完任务或拆新任务；偏差处理遵循[协作协议](04_Agent协作协议.md)。

执行状态仅由 Task 持有，通常写 `NotStarted / InProgress / Blocked / Done`；取消或替代按上表直接说明。任务完成不等于模块或游戏完成。当前契约应直接可读，不依赖阅读历史任务才能理解；仅长期高代价、难逆转的取舍在所属需求/API 正文保留理由与重评条件。

## 结果与保留边界

单次方法、结果、独立检查与限制简记在已有 Task、PR 或会话。长期回归保留测试源码、配置与可重现命令，运行日志和 XML 留工具临时输出或 CI。

不创建独立 Evidence、验证 README、测试/发布报告、来源哈希、历史归档或变相副本，也不把原始输出全文搬进既有正文。发布、疑难问题与文档整理使用同一规则；清理报告不删除测试源码和命令。外部项目仅供参考，适用结论写入当前规则，不复制来源文档或生成阅读记录、治理流水与全局台账。

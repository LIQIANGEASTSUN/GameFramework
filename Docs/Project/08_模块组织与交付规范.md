# 模块组织与交付规范

模块应有清楚的边界、工作入口、当前状态和交付责任。协作执行[协作协议](04_Agent协作协议.md)，质量与验收执行[工程标准](05_工程实施与验收标准.md)，通用文档维护执行[文档组织规范](06_文档组织规范.md)。

## 1. 模块边界与根

- 按独立职责、契约、生命周期或验收边界划分模块并指定负责人；功能子模块从父模块需求链接，共有规则不互抄。
- 项目系统的模块根按[项目架构](02_架构与模块.md)确定，`Assets/Game/<模块>/` 仅为默认位置；用户已指定的目录优先，不得按默认规则自动迁移。包内能力以所属能力目录为模块根，独立包以仓库根为入口；模块不等同于独立仓库、包或程序集。
- 跨包实现保留在正确层，由主责模块链接权威契约与适配入口，不为模块内聚迁移或复制其他层的实现。
- 项目级资料只维护总体目标、共同规范、模块入口与真正项目级集成；项目模块沿 02 发现，包内能力按包 README 的目录约定查找功能需求，功能子模块沿父模块需求发现，不要求全部子模块登记到全局或包 README。

## 2. 入口与工作资料

独立包根 README 简洁维护稳定的框架职责、边界、依赖、程序集、组合使用与文档组织约定；只有这些规范变化时修改，不随功能扩展登记能力或状态，也不另建包根需求或功能索引。

功能模块根就近组织以下资料；包内能力按包 README 的目录约定定位模块根。按实际规模保留必要内容，不创建空文档或空目录，不另设功能模块 README：

```text
<模块根>/
  Docs/
    需求.md
    Tasks/<具体交付>.md
  <所属代码、资源与测试>
```

- `Docs/需求.md` 是功能模块需求入口，写明职责、目标、边界、依赖、对外行为、用法与验收，直接导航 Task，不承载动态进度；涉及包级框架约束时显式引用相应包 README。未实现时不将规划能力或示例冒充已交付事实。
- Task 引用需求与验收，继承需求显式引用的包 README 规范，另行涉及的包规范须补充引用；按[可独立实施标准](06_文档组织规范.md#可独立实施的文档)写清接口约定、状态机、必要实施方案和验证预期；接口及验收所需示例就近放入对应章节。实现前后保留规范正文，状态与必要结果另记。
- 实际源码、测试入口在 Task 对应章节导航；不另写一套现状 API 文档作为契约。独立包须显式定位其规范依赖，复制模板时修正相对链接，不能删除独立实施必需的规则。

## 3. Task 分工与交付状态

- 执行信息按[文档职责](06_文档组织规范.md#规范正文与执行记录)唯一维护在所属 Task。需求或交付范围、关键阻塞、集成或验收结论变化时，更新受影响 Task 的相应内容，不在需求中抄写动态进度，不因查询或会话生成快照。
- Task 负责人按具体实现与执行维护状态和结果，使用 `NotStarted / InProgress / Blocked / Done`。单套可在头部记录状态；多套时头部指向本 Task 的执行记录与结果，各套分别记录状态、产物和验证，不相互覆盖或代用。取消或替代时保留原因、交付范围与替代入口。
- 消费方在自身 Task 记录所需输入、当前依赖缺口及其影响，提供方的执行状态通过引用其 Task 查询，不复制状态枚举或建立状态台账。
- 不另设状态或汇总文档；多个 Task、跨模块依赖、删除 README 或导航需要均不构成新增理由。联合交付由实际承担集成的 Task 承接，没有真实集成交付时不预造汇总 Task。

## 4. 提供与依赖契约

- 同时明确本模块提供什么、需要什么；按实际边界说明契约负责人、实现方与消费方、数据与生命周期、就绪、失败、兼容及可判定条件。
- 已有契约直接引用需求、Task 或其显式规范依赖中的定义，通用契约与项目专属实现遵循架构归属；不为尚未成立的需求预造接口或扩展机制。

## 5. 推进与验收

- 开工前从模块入口确认目标与边界、必要输入及就绪条件、任务依赖顺序、唯一写入范围和验证入口与判据。条件未满足时按协作协议推进可独立部分，不掩盖缺口。
- 所有跨模块工作须明确最终集成者。有自然业务归属时，由主责模块持有联合需求与验收，其他模块的 Tasks 引用；真正项目级集成才由项目层承接。实际承担集成的 Task 负责联合交付与验收，引用提供方 Task 而不抄写其状态。各 Task 对应实现为 Done 不等于约定的模块联合验收完成。
- 按工程标准验证真实交付，不能用替身或局部测试冒充真实集成，必要验证未完成不得宣称完成。交付后在所属 Task 记录必要执行结果。需求与 Task 的规范正文默认不改，实际问题先讨论修正；修订条件及用户另行授权按[后续修改规则](06_文档组织规范.md#后续修改与当前结论)处理，不因实现完成改正文。
